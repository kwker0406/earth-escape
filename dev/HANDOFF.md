## 4. 꼭 지킬 것

**보안**
- 서비스 계정 열쇠(JSON)는 GitHub Secrets `FIREBASE_SERVICE_ACCOUNT`에만 있다. 사용자에게 보내 달라고 하지 않고, 파일로 만들지 않고, 채팅에 적지 않는다.
- 저장소의 `config.js`(실제 Firebase 설정)는 덮어쓰지 않는다.
- PixelLab 계정 페이지에는 비밀 API 키가 보인다. 어디에도 복사하지 않는다. 계정 만들기·비밀번호 입력·결제는 사용자가 한다.
- 사용자 이메일은 공개 저장소에 넣지 않는다(시험용 가짜 로그인은 `teacher@example.com`).
- `database.rules.json`에서 `sessions`·`classes`·`codes` 구역을 지우거나 바꾸면 게임이 멈춘다.

**커밋**
- 작성자는 `Claude <noreply@anthropic.com>` (`git -c user.name=Claude -c user.email=noreply@anthropic.com commit`). 개인 이메일로 push하면 거절된다.
- earth-escape, class-games 두 저장소에 push해도 된다고 사용자가 허락했다.

**그림·소리**
- 저작권 캐릭터를 그리지 않는다. 아오오니 음악을 따라 만들지 않는다. "좀비고"는 분위기만 참고한다.
- 교복의 빨간 리본은 "빨간 끈을 리본 모양으로 묶은 넥타이"다. 진짜 리본을 달지 않는다.
- 학생이 입력한 글(닉네임 등)은 `textContent`로만 화면에 넣는다.

**말하기(사용자 선호)**
- 항상 한국어, 짧은 문장. 영어 답을 싫어한다.
- 주장에는 [사실]/[추측]/[의견] + 확신도(높음/중간/낮음) + 이유 한 줄.
- 계획·초안에는 빠진 점·위험부터 짚고, 대안 2~3개와 추천안.
- 요청이 모호하면 질문 1~3개 먼저.
- 고친 것이 있으면 끝에 "자체 점검: ..." 한 줄. 끝에 "확인하지 않은 것"도 적는다.
- 가장 작은 변경으로 끝낸다(요청하지 않은 기능은 넣지 않는다).

### 퍼즐·단서 (`puzzles.js`)

- 난이도별로 끄는 퍼즐: 어려움 없음 / 보통 `f4c` / 쉬움 `f4c, f4a, f3a, f3b`.

## 6. 시험에 대해 알아 둘 것

- `check.py`가 자주 멈추던 원인을 찾아 고쳤다(2026-11-15). 시험 도구가 Firebase 주소를 **가로채는 방식**이 가짜 Firebase의 "멈추고 기다리는 통신"과 겹치면 새로고침에서 교착이 났다. 지금은 시험 서버(`fakeserver.py`)가 파일을 내줄 때 주소를 가짜 파일로 바꿔 준다. `ctx.route`로 되돌리지 말 것.
- 그래도 타이밍 때문에 가끔 한 항목이 실패한다(예: "시작 후에도 안내가 가림", "다시 받기 실패"). 한 번 더 돌려서 통과하면 타이밍 문제다. 같은 항목이 연달아 실패하면 진짜 문제로 본다.
- `perf.py` 결과(30명, 2026-11-15): 보통 폰 초당 60장, 4배 느린 폰 46장, 6배 느린 폰 40장, 선생님 화면 60장, 페이지 오류 0, 30명 입장 중복 0.
- 가짜 Firebase로만 시험한다. 실제 서버 지연, 요금제 동시 접속 한도, 학교 와이파이는 **확인하지 못했다**. 수업 전에 학생 5~6명과 실제 폰으로 5분 미리 돌려 보라고 권했다.

## 8. 겪은 문제와 배운 것

- 코드로 직접 그린 캐릭터는 세 번 거절당했다("밤티", "최악"). PixelLab 생성으로 바꾼 뒤 통과했다. 새 캐릭터는 생성하고, 색·옷만 다르면 고쳐 만든다.
- 안경을 지우는 것은 안 된다(눈이 렌즈와 한 덩어리로 그려져 있음). 안경 없는 얼굴을 다른 그림에서 가져와 붙인다.
- 화면 그리기를 고치면 `perf.py`를 꼭 돌린다. 밤 효과를 넣고 안 돌렸다가 느린 폰에서 초당 24장까지 떨어진 적이 있다.
- 팀은 함께 층을 옮긴다(과반이 계단 앞에 모이면 모두 이동). 팀원이 혼자 다른 층에 있을 수 없다.
- 사용자는 그림을 확대본으로 꼼꼼히 본다. 고친 뒤에는 확대 그림을 함께 보내고, 어색한 점을 먼저 말한다.
